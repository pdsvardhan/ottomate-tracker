# WS-D — Playwright E2E Plan (for a dedicated session)

**Status:** PLAN ONLY (owner asked to dedicate a separate session to building this).
**Risk addressed:** risk-1 (no-tests) — 35 vitest contract tests are green, but **0 of 55 flows have browser-level E2E**, so there is no regression net for the UI.
**Pairs with:** adr-020 CI policy (`RUN_TESTS` toggle + prebuilt Playwright image) — WS-E #9.

## Goal
Stand up Playwright against the Ottomate app and author E2Es for the highest-value flows first, wiring them so they run under the `RUN_TESTS=true` gate (hard at the production deploy gate, off pre-prod). Then phase outward toward the 55 flows.

## Harness setup
1. `@playwright/test` is already a devDep path in the canonical CI image (`mcr.microsoft.com/playwright`). Add `playwright.config.ts`: `baseURL` from `E2E_BASE_URL` (default `http://localhost:3000`), `webServer` to boot `next start` for local runs, projects for desktop + mobile viewports, `trace: 'on-first-retry'`.
2. `tests/e2e/` directory; `npm run test:e2e` → `playwright test`.
3. Seed strategy: run against a **disposable copy of the DB** (the fresh-catchup schema + a small seed), never the live `ottomate.db`. A `tests/e2e/global-setup.ts` provisions it; teardown drops it.
4. CI: the canonical `ci.yml` `tests` job already runs `npx playwright test` under `RUN_TESTS`; no CI change needed beyond turning the var on once tests exist.

## Critical-flow priority (build these first — they protect the anti-gaslighting bedrock + the showcase)
Tier 1 (the bedrock — must never silently break):
1. `flow-iteration-detail-lock` — lock-in gate locks an iteration (no code-before-lock is the whole point)
2. `flow-iteration-detail-items` / `-edit-item` / `-reject-item` — items render + are editable pre-lock
3. `flow-iteration-detail-trace` — trace report renders post-integrate
4. `flow-classify-report` / `flow-integrate` (backend) — report → items → integrate happy path

Tier 2 (showcase legibility — recruiter-facing):
5. `flow-projects-grid` + `flow-projects-click-card` — list → overview
6. `flow-project-overview-pipeline` + `-key-context` + `-docs-rail` (now that WS-F ships docs)
7. `flow-architecture-process/topology/data` — diagrams render + zoom

Tier 3 (the now-working catalog — guard the WS-A fix):
8. `flow-components-grid` + `flow-component-detail-preview` — preview renders (no "Could not find dependency" regression)
9. `flow-inspirations-grid` (after the deferred inspirations session)
10. `flow-coverage-heatmap`, `flow-inbox-*`, remaining grids/filters

## Phasing
- **Phase 1 (this E2E session):** harness + Tier 1 (4-5 specs). Flip `RUN_TESTS=true` on `ottomate` only. Update each tested flow's `test_status` via the API as specs pass.
- **Phase 2:** Tier 2 + Tier 3.1 (showcase + catalog preview guard).
- **Phase 3:** sweep the long tail of grid/filter flows; consider a coverage report tying specs → flow ids.

## Definition of done (per phase)
- Specs green locally + in CI under `RUN_TESTS=true`.
- Tested flows' `test_status` flipped from `not-tested` in the tracker (honest coverage, no overclaiming).
- risk-1 notes updated with the real covered-flow count (do not mark risk-1 resolved until critical flows are covered).

## Out of scope
- 100% of 55 flows in one pass (phased deliberately).
- Visual-regression / Lighthouse (adr-014: only where the tool is actually deployed).
