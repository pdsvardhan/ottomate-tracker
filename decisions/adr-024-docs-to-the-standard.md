# adr-024: This project's docs follow the documentation standard; hand-written status docs are retired

- Status: accepted · Date: 2026-09-07 (owner-directed: to-do #837, split from #393 on 2026-09-07) · curated · cat:reliability
- Supersedes, in part: adr-016 (its `generate-status.sh` clause — the script was never built)

## Context

The documentation standard (skill `references/documentation-standard.md`) puts every doc in exactly one layer: the
registry is canonical, reference docs are generated from it, hand-written docs explain *why*, and stand-alone
hand-written briefs that restate the registry are to be retired, not maintained. Enforcement (doc-lint: Vale + lychee +
native checks, ramped by `projects.doc_gate`) shipped in August and is at `block` on three projects.

This repo — the tracker itself — was not at the standard. It carried eleven hand-written documents from April–June 2026
that restate what the registry now holds: `STATUS.md`, `DONE.md`, `PENDING.md`, `TODO.md`, `CUTOVER.md`,
`PILOT_ONBOARDING.md`, `SKILL_OVERVIEW.md`, `TRACKER_OVERVIEW.md`, `REQUIREMENTS.md`, `HANDOFF.md`, and the pre-ADR
`DECISIONS.md` register. Every one was last touched on or before 2026-06-10. adr-016 had already ordered
`REQUIREMENTS.md` and `PILOT_ONBOARDING.md` archived and `STATUS.md` generated by `scripts/generate-status.sh`; the
archive move never happened in this repo and the script was never written — SKILL.md rule 15 pointed at it for three
months. There was no `ARCHITECTURE.md`; the architecture existed as three `.mmd` diagrams and two April "overview" docs.
The context diagram still showed a "planned secrets vault" that adr-014 had removed from every gate.

## Decision

1. **The doc set for this project is:** `README.md` (orientation + how-to), `ARCHITECTURE.md` (arc42-lite, C4 diagrams
   from `architecture/*.mmd`), `decisions/adr-*.md` (MADR, supersede-don't-delete), `public_docs/*` (showcase
   narrative, each opening with an as-of line), `CODING_GUIDELINES.md`, the YAML mirror, and the **generated**
   `FEATURES.md` (`gen-reference-docs.mjs`, provenance header, never hand-edited).
2. **The eleven hand-written status/requirement documents are retired** to `_legacy/docs-retired-2026-09-07/` with an
   index. Nothing there is maintained; it exists for archaeology. The registry, `FEATURES.md` and the showcase progress
   page are the status view. adr-016's `generate-status.sh` clause is superseded by this: the generated status doc is
   `FEATURES.md`, and the pack-up ritual regenerates it.
3. **`doc_gate` moves `off → warn`** for this project now, and to `block` after one clean pack-up cycle shows the rules
   fire here (the ramp discipline in the standard §6).
4. **The dead "planned secrets vault" node is removed** from `architecture/system-context.mmd`; the retired tool names
   from adr-014 become this project's Vale reject-seed so they cannot come back into a live doc.

## Consequences

- Anyone looking for "what is the status" reads the showcase or `FEATURES.md`, not a file that was true in April.
- `README.md` links to the generated reference, the architecture, the decisions and the narrative — and to the retired
  set, so the history is one click away, not gone.
- Skill rule 15 and the pack-up ritual now name the real steps (`gen-reference-docs`, `doc-lint`), and the standard's
  header stops calling itself a draft.
- Cost: the retired docs' cross-references to each other go stale inside `_legacy/`; that is accepted — they are not
  linted and not maintained.
